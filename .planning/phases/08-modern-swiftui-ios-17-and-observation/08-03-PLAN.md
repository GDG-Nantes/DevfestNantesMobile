Repository facts (verified while planning):
- `VenueViewModel` (v1.0): `@MainActor class VenueViewModel: BaseViewModel`, published `venueContent: VenueContent?` and `isLoading: Bool = true`; computed `currentLanguage: ContentLanguage` (`Locale.current.languageCode == "fr"` gives `.french`, otherwise `.english`); `observeVenue()` sets `isLoading = true` then starts an unstructured task that awaits `asyncFunction(for: store.getVenue(language: currentLanguage))` and assigns `venueContent = VenueContent(from: venueData)` and `isLoading = false` through main-queue hops; on error it logs `DevFestLogger(category: "Venue").log(.error, "Observe Venue error: \(error.localizedDescription)", error: error)` and sets `isLoading = false`. No performance trace.
- `VenueView` owns it with `@ObservedObject var viewModel = VenueViewModel()`, uses `$viewModel.isLoading` for `LoadingView` and `viewModel.venueContent`, and already calls `await viewModel.observeVenue()` in `.task`.
- `VenueContent(from:)` force-casts `venue.latitude`/`venue.longitude`: a hand-built `Venue` with nil coordinates would crash, and building non-nil ones needs `KotlinDouble`, a Kotlin name Swift does not reference yet (it would force a swift-names baseline regeneration). Fakes therefore return the `Venue` fixture read once from the mocked store (`LiveVenueSource(store:)` over `DevFestNantesStoreBuilder().setUseMockServer(useMockServer: true).build()`, which returns `buildVenueStub(language)`: English and French descriptions differ). This is a Kotlin fixture value in the sense of D-07.
- Shared pieces from 08-02: `KotlinStreamBridge`, `FakeStream`, the `Fakes` group, the four-entry project rule, the hosted test conventions, `DevFestNantesStoreBuilder` already in the swift-names baselines (no regeneration needed in this plan).
- `SpeakersVenueCharacterizationTests` calls `VenueViewModel().currentLanguage` after `TestHost.start()`.
