## Discretion decisions taken in this plan (CONTEXT "Claude's Discretion")

- **Names** (no Swift collision, RESEARCH verified with git grep over iosApp Swift sources): `DaySchedule(dayIndex: Int, date: String, slots: List<TimeSlot>)` and `TimeSlot(start: Instant, sessions: List<Session>)` as data classes (`kotlin.time.Instant`); `AgendaDay` is not reused (it exists in `:core:model` and in the Swift header).
- **DayAssignment** = `sealed interface DayAssignment` with `data class UtcDayWindows(val dayStarts: List<String>)` (Android: ISO instants such as `Agenda.DAY_ONE_ISO`; `DaySchedule.date` = that string) and `data class LocalDateDays(val dates: List<String>, val timeZone: TimeZone)` (iOS: `yyyy-MM-dd` local dates in `timeZone`; `DaySchedule.date` = that string). Days are emitted in configured order with `dayIndex` = position + 1, always all of them (Android shows both tabs even when empty). The lookup is an `internal` function (not exported). Invalid day-start strings never throw: they parse with `toInstantOrNull()` and simply match nothing. The 2025 dates stay single-source in `Agenda.DAY_ONE_ISO`/`DAY_TWO_ISO` (debt FUT-06): tests derive the iOS dates with `substring(0, 10)`.
- **Time zone and clock (D-05), with a recorded deviation on the Android path**: D-05 asks every use case to take the zone explicitly from each platform. The zone is an explicit parameter wherever it changes the result: iOS passes `TimeZone.currentSystemDefault()` inside `LocalDateDays`. The Android strategy `UtcDayWindows` reproduces the fixed 24 h UTC windows of `Agenda.Builder`, whose output depends on no zone (grouping by Instant is zone-free), so no ignored zone argument is added to it; the Android device zone stays where v1.0 used it, in the slot-label formatter of the Android UI (07-15). This D-05 deviation is recorded in the SUMMARY and in the 07-13 deviations table, and `DayAssignmentTest` proves the zone independence. No `Clock` parameter: no shared use case needs "now" because scrolling to the current slot stays per platform (D-08; RESEARCH "Do not add an unused Clock parameter").
- **Slot order** is chronological by Instant; v1.0 Android sorted by the `startDate` string, which is identical on the recorded data (uniform `+02:00` offset, whole minutes: proven by 07-04 facts). Recorded in the 07-13 deviations table.
- **Filter output order**: input (store) order. v1.0 Android went through a `HashSet` (unspecified order), so this is a deterministic subset of the old behavior (RESEARCH).
- **Golden comparison** uses `GoldenFiles` / `Goldens` / `FilterCases` from `:core:testing` (07-05) with the canonicalization rules of the README; the shared code itself is never canonicalized, its real order is asserted separately.
