## Discretion decisions taken in this plan

- **No `@SerialName`**: the JSON holds only `type` and `value` and enum entries serialize by entry name, so moving the enum to top level does not change bytes (RESEARCH A3); the literal-JSON assertions of `SessionFiltersServiceImplTest` running on the moved class are the proof.
- **Codec placement**: `SessionFilterCodec` is `internal` to `:core:data` (only the stores use it; not exported to Swift). It uses the default `Json` instance exactly like `SessionFiltersServiceImpl` (`Json.encodeToString(SessionFilter.serializer(), it)`, `Json.decodeFromString<SessionFilter>(raw)`), exposing `encode(filter): String`, `decode(raw): SessionFilter` (throws like today, so the Android store can keep its Timber error lines in 07-09) and `decodeOrNull(raw): SessionFilter?` (catches `SerializationException` and `IllegalArgumentException`).
- **Store interface shape** (RESEARCH Pattern 2): `@NativeCoroutinesState val filters: StateFlow<Set<SessionFilter>>`, `fun setFilters(filters: Set<SessionFilter>)`, same contract as today's `SessionFiltersService`, so `AgendaViewModel.sessionFilters` and `HomeViewModel` keep a `StateFlow`.
- **D-14 deviation record**: documentation/ARCHITECTURE.md gets a "Behavior deviations (v1.1)" subsection (created here, extended by 07-08): "`SessionFilter` is a data class: equal-content filter sets no longer re-emit through `StateFlow`; no visible effect (07-03 drawer and equality characterizations unchanged)".
