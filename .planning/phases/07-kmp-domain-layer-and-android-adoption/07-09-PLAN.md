## Discretion decisions taken in this plan

- **Two-step move (scope split, each plan under 15 files)**: this plan adds the shared type, its Swift-side handling and the store contract; 07-10 switches every Android consumer listed in `<interfaces>` and deletes the feature/agenda copy. Until then two `SessionFilter` classes exist in different packages; every Android file imports its class explicitly, so nothing is ambiguous (Task 1 compiles feature/agenda to prove it).
- **D-13 exception to the AGENTS.md baseline rule**: AGENTS.md regenerates baselines only together with a matching Swift call-site change; D-13 (locked) requires regenerating them in the export commit with no Swift change. Task 1 follows D-13 and records the exception in its commit message body and in the SUMMARY.
- **No `@SerialName`**: the JSON holds only `type` and `value` and enum entries serialize by entry name, so moving the enum to top level does not change bytes (RESEARCH A3); `SessionFilterCodecTest` pins the same literal JSON here, and the unchanged literal-JSON assertions of `SessionFiltersServiceImplTest` running on the shared class in 07-10 are the Android proof.
- **Codec placement**: `SessionFilterCodec` is `internal` to `:core:data` (only the stores use it; not exported to Swift). It uses the default `Json` instance exactly like `SessionFiltersServiceImpl` (`Json.encodeToString(SessionFilter.serializer(), it)`, `Json.decodeFromString<SessionFilter>(raw)`), exposing `encode(filter): String`, `decode(raw): SessionFilter` (throws like today, so the Android store can keep its Timber error lines in 07-16) and `decodeOrNull(raw): SessionFilter?` (catches `SerializationException` and `IllegalArgumentException`).
- **Store interface shape** (RESEARCH Pattern 2): `@NativeCoroutinesState val filters: StateFlow<Set<SessionFilter>>`, `fun setFilters(filters: Set<SessionFilter>)`, same contract as today's `SessionFiltersService`, so `AgendaViewModel.sessionFilters` and `HomeViewModel` keep a `StateFlow`.
- **D-14 deviation record**: documentation/ARCHITECTURE.md gets a "Behavior deviations (v1.1)" subsection (created here, extended by 07-13): "`SessionFilter` is a data class: equal-content filter sets no longer re-emit through `StateFlow`; no visible effect (07-06 drawer and equality characterizations unchanged)".
