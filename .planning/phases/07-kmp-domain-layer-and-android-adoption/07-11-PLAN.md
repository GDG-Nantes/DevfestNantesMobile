- **D-15 is a one-way door already walked through by the user** in discuss-phase (CONTEXT D-15, PROJECT.md Key Decisions): no `checkpoint:decision` is inserted; the `one-way` rating is recorded on the tasks for traceability.
- **Key names and stored types (CONTEXT discretion)**: `devfest.bookmarks.sessionIds` = `NSArray` of `NSString` session ids; `devfest.agenda.filters` = `NSArray` of `NSString`, one `SessionFilterCodec.encode` JSON per filter. Both differ from `Favorites` and `AgendaSessionFilters`.
- **Visibility**: both classes are `internal` (bound in the internal `dataPlatformModule`, tested from `core:data` iosTest), so they do not enter the Swift header and the swift-names gate is untouched.
- **State handling** (RESEARCH Pattern 2): constructor takes the `NSUserDefaults` instance (tests pass a unique suite); state lives in a `MutableStateFlow` loaded once in the constructor; writes use `update {}` then persist `state.value` (do not copy the unsynchronized `HashSet` mutation of the Android `BookmarksStoreImpl`). `subscribe(id)` mirrors Android: `state.map { id in it }`.
