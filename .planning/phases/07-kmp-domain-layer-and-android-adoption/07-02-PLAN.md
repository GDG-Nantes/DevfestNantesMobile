## Discretion decisions taken in this plan

- **Recorder = gated JVM test, wrapped by a script** (D-09 "a small documented script or task"): `AgendaSnapshotRecorder` in `core/data/src/jvmTest` posts each query's generated `OPERATION_DOCUMENT` (the exact document the app sends, with compiler-added `__typename`) with `java.net.http.HttpClient`; it is excluded from `jvmTest` unless `-PrecordAgendaSnapshot` is set (same gating style as `-PliveNetworkTests`). `scripts/record-agenda-snapshot.sh` runs the recorder, then the neutral rewrite, in two Gradle invocations so the order is guaranteed.
- **Files, not Kotlin constants** (RESEARCH Pitfall 1 and alternatives table): GetSessions is about 213 KB. Raw files live in `core/data/testdata/graphql/`, neutral files in `core/domain/testdata/agenda/` (not a resources dir; read through absolute paths passed by Gradle).
- **Writer and reader are split to avoid a project cycle**: the writer (`AgendaSnapshotJson`, `buildJsonArray`/`buildJsonObject`) lives in `:core:data` jvmTest; the reader (`AgendaSnapshot`, `@Serializable` DTOs) lives in `:core:testing` commonMain (`:core:testing` depends on `:core:data`, so `:core:data` tests must not depend on it). The committed JSON and README are the contract.
- **Golden-file conventions for the whole phase are defined here**, in `core/domain/testdata/agenda/README.md`, so plans 07-03 (Android) and 07-04 (iOS) can run in parallel without touching the same file.
