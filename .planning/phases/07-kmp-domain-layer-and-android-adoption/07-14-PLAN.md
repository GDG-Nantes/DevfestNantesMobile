## Decisions taken in this plan

- **Why a bridge (scope split of the former single switch plan)**: SHARED-06 requires the service removal and the binding replacement in the same commit, and the RESEARCH anti-pattern forbids two holders over one preference key. Putting the consumers on the interface first (this plan) keeps both rules and leaves the atomic commit of 07-16 small. The bridge only adds a supertype and a secondary binding type to the existing single definition; it never creates a second instance.
- **Smoke test wiring**: `KoinTestRule` allows overriding and `androidTestDoubles` (listed after `agendaModule`) binds `FakeSessionFiltersStore` since 07-09; without a fix the fake would win for `SessionFiltersStore` while the test asserts on the real service. The last test module therefore adds `single<SessionFiltersStore> { get<SessionFiltersService>() }` so the ViewModel and the assertion see the same real instance over the test preferences.
- **"Unchanged" = wiring-only (D-18)**: only types, imports, Koin test bindings and verify extra types change in tests.
