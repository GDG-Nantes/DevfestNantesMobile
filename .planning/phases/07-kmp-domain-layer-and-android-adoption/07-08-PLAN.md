## Discretion decisions taken in this plan

- **No app source change**: only the test target gets new `project.pbxproj` entries (the project lists every file explicitly, RESEARCH Pitfall 7).
- **Entry points under test = v1.0 code (D-11)**:
  - Grouping: `let vm = AgendaViewModel()`, `vm.sectionDateFormatter.timeZone = zone`, `vm.sessionsChanged(sessions: snapshot)`, then `vm.agendaContent.sections`. Setting the zone on the existing formatter instance is test configuration equivalent to a device in that zone (on a device the formatter's default zone is `TimeZone.current`; the section keys come from the zone-free `parseDate`). The grouping body is the unchanged v1.0 code (07-07 only dropped `private`).
  - Filtering: the D-10 statics `AgendaView.sections(_:forDay:)` and `AgendaView.filteredSessions(_:filters:favorites:)` (07-07).
  - Speaker alphabet: `let vm = SpeakersViewModel()`, `vm.speakersContent = snapshotSpeakers`, then the unchanged `vm.getAlphabets()` and `vm.speakers(for:)`.
  - Venue language: the unchanged `VenueViewModel().currentLanguage`. `Locale.current` cannot be injected without changing the app, so the test asserts the row of the shared table (nil, "fr", "en", "de", "" -> english except "fr" -> french, identical to `VenueLanguageUseCaseTest`) selected by the run's `Locale.current.languageCode`; the other rows are pinned on the Kotlin side and by the 07-06 Android table.
  - Classification: the unchanged `AgendaContent.Session(from:).isATalk`. The navigable check stays a private view expression and is not pinned here (see 07-07: not moved in Phase 7, characterized by the Phase 9 plan that replaces it).
  - ViewModel creation: tests call `IosDependencies.shared.start()` first (idempotent; the host app already called it at launch, so no second Koin start) and only use the initializers, the methods above and `speakersContent`/`sectionDateFormatter`; never `observe*`, `toggleFavorite`, `clearFilters` or `sessionFilters` assignment.
- **Goldens** follow core/domain/testdata/agenda/README.md: `dayIndex` 1/2, `date` = the tab id (`2025-10-16`, `2025-10-17`), slot `start` = `ISO8601DateFormatter().string(from: section.date)` (UTC, `Z`), slot ids canonicalized by (room name or empty string, id) because Swift `sort` does not guarantee stability among equal room names. Swift writes them with `JSONEncoder` `[.prettyPrinted, .sortedKeys, .withoutEscapingSlashes]`; consumers parse JSON (no byte-level cross-writer comparison).
- **Golden rule (README, 07-04)**: present file -> exact string comparison; absent file in a default run -> `Issue.record("golden missing: <path>")` and nothing is written; absent file in record mode (`ProcessInfo.processInfo.environment["DEVFEST_RECORD_GOLDENS"] == "true"`, passed by prefixing `TEST_RUNNER_DEVFEST_RECORD_GOLDENS=true` to the `xcodebuild ... test-without-building` invocation, which forwards `TEST_RUNNER_`-prefixed variables to the test process without the prefix) -> write it and `Issue.record("golden recorded, re-run: <path>")`. An existing golden is never overwritten. Same rule as the Kotlin `GoldenFiles`.
- **Time zones**: `Europe/Paris` and `Pacific/Auckland` (`TimeZone(identifier:)`); in Auckland late day-1 sessions move to the 2025-10-17 tab and late day-2 sessions fall on 2025-10-18, which no tab shows: this is today's behavior and is pinned as is.
