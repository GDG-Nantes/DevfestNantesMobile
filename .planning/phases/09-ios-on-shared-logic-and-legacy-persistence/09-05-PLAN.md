Facts (verified while planning):
- `ClassifySessionUseCase` has `init()`, `isTalk(session:)`, `isNavigable(session:)`, `isService(session:)`. Table: talk = typed and not opening, break or lunch; navigable = quickie, conference, codelab; keynote is a talk but not navigable; no type is none of them.
- Today `AgendaContent.Session.isATalk` is a computed `switch`, and `AgendaView.agendaRow` computes `isNavigable` from three type comparisons. Both match the shared table.
- `AgendaContent.Session` is built in `AgendaViewModel.sessionsChanged`, twice in `SpeakerDetailsView.swift` (lines 71-72, app target), and in tests. A test-only overload cannot reach the app target, so the one-argument `init(from:)` stays through this plan and 09-06 deletes it with its last app call site.
- Name resolution trap: inside `extension AgendaContent.Session`, unqualified `Session` binds to the Kotlin type, as the existing `init(from:)` shows. Inside `extension AgendaContent` it would bind to the nested struct.
- `AgendaContent.Session.init(from:)` is called from `AgendaViewModelTests` and `AgendaCharacterizationTests`. Those call sites stay unchanged in this plan.
- The hosted `live_source_...` test in `AgendaViewModelTests` documents "no network, Firebase or Koin": give it `classify: { ClassifySessionUseCase() }`.
