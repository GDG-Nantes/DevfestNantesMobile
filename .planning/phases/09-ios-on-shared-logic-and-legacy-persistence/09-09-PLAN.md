Facts (verified while planning):
- App: scheme `iosApp`, product `DevFest Nantes.app`, bundle id `com.gdgnantes.devfest.iosApp`. Debug builds need the gitignored `iosApp/iosApp/GoogleService-Info.plist` and, in a fresh worktree, the gitignored `local.properties`; both exist locally.
- `main` holds the Phase 8 merge (`1077fd84`): its `AgendaViewModel.swift` persists on the legacy keys. The Phase 8 harness built the baseline in a detached worktree outside the repository, and this plan does the same.
- `maestro` 1.35.0 is at `/opt/homebrew/bin/maestro` and drives simulators through `maestro --device <udid> test <flow>`. Targets from `08-parity/parity-flow.yaml`: star buttons by id `star` and `star.fill`, filter menu at `point: "89%,10%"`, labels `Favorites`, `Clear`, day-1 readiness on visible text `08:00`. Flow commands: `launchApp`, `stopApp`, `tapOn`, `scrollUntilVisible`, `extendedWaitUntil`, `assertVisible`, `assertNotVisible`, `takeScreenshot`.
- The Phase 8 flow resets state at launch. A flow that does that after the install would pass while proving nothing (RESEARCH Pitfall 8), so the verify flow is a separate file.
- Preferences live in the app data container: `xcrun simctl get_app_container <udid> com.gdgnantes.devfest.iosApp data`, then `Library/Preferences/com.gdgnantes.devfest.iosApp.plist`. Read with `plutil -p`, and extract one key with `plutil -extract <key> xml1 -o - <plist>`. The preferences daemon can write a moment after the app stops: if a key is missing right after a stop, launch and stop the app once with `xcrun simctl launch` and `xcrun simctl terminate`, then read again.
- A1 (RESEARCH): `xcrun simctl install` over the same bundle id keeps the data container. The legacy values surviving on disk are what proves it, more than an equal path.
- Checkpoint mode: `workflow.human_verify_mode` is `end-of-phase`, but D-09 (locked) requires a human checkpoint, so it is `gate="blocking-human"`, never auto-approved (07-19 and 08-09 precedent).

Execution notes:

- Do not create, switch or rename branches. The worktree is detached and stays in place for 09-10, which removes it.
- Stop-and-report rule, for every step: if a build fails, Maestro cannot drive the simulator, or a screen cannot be reached, stop, commit nothing, and return the blocker as blocking-human with the failing output. Never copy a secret into a tracked path.
