Facts (verified while planning):
- `ObserveAgendaUseCase.observe(dayAssignment:timeZone:)` is a native flow of `[DaySchedule]`, same shape as `store.sessions`, so `KotlinStreamBridge.stream` accepts it. The flow is built per call and re-reads `store.sessions`, so each subscription reloads. `combine` keeps it open after the sessions complete, because the two stores never complete. Equal consecutive results are not filtered.
- The shared output has both configured days, always; a day with no match has no slots, and no slot is empty. `DaySchedule.date` is the configured string, so sections of a day are selected by equality with `AgendaDays.day1` or `day2`.
- `TimeSlot.start` is a `KotlinInstant` with `epochSeconds`; recorded starts are whole seconds. `TimeSlot.sessions` is already in `RoomSortIndex` order: the mapping must not sort.
- Name resolution trap: inside `extension AgendaContent`, unqualified `Session` is the nested struct. Write `shared.Session` for the Kotlin type there. Inside `extension AgendaContent.Session` it is the Kotlin type.
- `tracing.trackDataLoad` takes one `operation` closure. To end the trace at the first emission while keeping the same subscription, create the iterator before the call, await `iterator.next()` inside the closure, and keep using the same iterator after the call (RESEARCH Pattern 2). The target builds in Swift 5 language mode, so a captured `var iterator` mutated in the non-Sendable closure compiles. If it does not, hold the iterator in a small private final class in the ViewModel file.
- The bridge ends silently when the consumer is cancelled, so cancellation must be checked explicitly after `next()` returns, both inside the traced closure and after the loop. A Kotlin-side cancellation arrives as `CancellationError` while `Task.isCancelled` is false.
- v1.0 ended the loading state on any thrown error, cancellation included: `git show 5896f573:iosApp/iosApp/Agenda/AgendaViewModel.swift`, one catch-all. Phase 8 added the silent `CancellationError` branch, which is what WR-01 reports.
- `RecordingDataLoadTracing` records at the start of a trace only; `FakeStream` scripts are `.emit`, `.fail` and `.hang`. Both need one addition here.
- `.onChange(of: viewModel.isLoading)` drives the initial scroll, once, because `isLoading` is never set back to true (D-03).
- `RCValues.sharedInstance.fetchCloudValues()` stays first in the `.task`.
- The Live `agenda()` path is one line over the use case and has no hosted test, because Koin binds `GraphQLStore`. `ObserveAgendaUseCaseTest` covers the flow in Kotlin; D-09 and D-10 cover the path live. The existing hosted test keeps covering `rooms()`.
