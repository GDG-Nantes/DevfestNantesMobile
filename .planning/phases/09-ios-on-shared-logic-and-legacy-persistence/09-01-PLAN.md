Facts (verified while planning, on this branch):
- `IosDependencies` is a Kotlin `object` exposing only `start()` and `store()`; Swift spells it `IosDependencies.shared`. Service-locator access is allowed there by `scripts/di-gate.sh`.
- Koin binds both iOS stores as `single` on `NSUserDefaults.standardUserDefaults` (`core/data/src/iosMain/.../di/DataPlatformModule.ios.kt`) and every use case as `factory` (`core/domain/.../di/DomainModule.kt`).
- From `shared.h`: `SessionFiltersStore.filters` is a synchronous `Set<SessionFilter>` snapshot, `SessionFiltersStore.filtersFlow` is the native flow, `setFilters(filters:)` writes. `BookmarksStore.bookmarkedSessionIds` is the native flow with no snapshot, `setBookmarked(sessionId:bookmarked:)` writes. Both native flows have the same shape as `store.rooms`, which `KotlinStreamBridge.stream` already accepts.
- `KotlinStreamBridge.stream` calls `next()` after each `yield`; a real continuous flow has never gone through it.
- The Swift `SessionFilter` struct still shadows the Kotlin one. Test files that import both must write `shared.SessionFilter` for the Kotlin type and `DevFest_Nantes.SessionFilter` for the Swift one until 09-08 deletes the struct.
- The Debug app skips Koin start under XCTest; `TestHost.start()` in `CharacterizationSupport.swift` (or a self-starting accessor) starts it.
- The real `observe` flow is not used here on purpose: Koin binds `GraphQLStore`, so it would need the network. `ObserveAgendaUseCaseTest` covers the combined flow on JVM and iOS simulator, and D-09/D-10 cover it end to end.
- `swift-names-gate.sh baseline` scans `git ls-files`, so a new Swift file must be staged before the baseline runs. It scans the test target too. Current Swift suite total: 57 tests (count of `@Test` in `iosApp/DevFestNantesTests`, matching the last Phase 8 run).
- `shared.h` on disk may be stale. Rebuild it with `./gradlew -q :shared:linkDebugFrameworkIosSimulatorArm64` before any Swift compile check.
