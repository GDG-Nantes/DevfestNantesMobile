# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Nature of this contract: a freeze, not a design.** Phase 9 is a behavior-preserving data-layer switch
(IOSDATA-01/02/03). The v1.1 transverse rule is strict parity: no new screen, no new component, no new
copy, no token change. This spec therefore (1) pins the v1.0/Phase 8 iOS visual system the executor must
not alter, (2) defines the interaction and state contract of the agenda once it is driven by the shared
combined flow, and (3) lists the single accepted visible deviation. Sources: 09-CONTEXT.md D-01..D-11,
ROADMAP Phase 9 success criteria 1-4, REQUIREMENTS IOSDATA-01..03, and the SwiftUI sources under
`iosApp/iosApp/` as of commit a0e85137. No questions were asked of the user: every answer was already
locked upstream or is read from the code.

## Color

The app uses the SwiftGen `Asset` colors with separate light and dark variants (Display P3). The
screen surface is always the dark `DevFestSiteBackground` gradient; cards are glass or thin material.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `DevFestTheme.greenDark` 0x1F3A33 to `greenDarker` 0x0F1A18 to `nearBlack` 0x0B0E0E gradient | Screen background (`DevFestSiteBackground`) |
| Secondary (30%) | `.regular` glass (iOS 26) / `.thinMaterial` (iOS 17-25) | Row cards, slot header capsule, detail cards, tab bar |
| Accent (10%) | `Asset.devFestRed` — light P3 (0.604, 0.271, 0.133), dark P3 (1.000, 0.706, 0.604); also the `TabView` accent | See reserved list below |
| Secondary accent | `Asset.devFestYellow` — light P3 (0.298, 0.404, 0.031), dark P3 (0.694, 0.824, 0.424) | Bookmark star and category chip fill/stroke only |
| Destructive | none declared | The only destructive-looking action is "clear filters", which uses the default menu styling (no red) |

Accent (`devFestRed`) reserved for: session title in a row, session title and "Speaker" heading in the
detail, the feedback link text, the active tab tint. Accent (`devFestYellow`) reserved for: the
bookmark star (`star` / `star.fill`) in the row and in the detail toolbar, and the `CategoryView`
chip. Selected filter state is indicated by `checkmark.square` / `star.fill` in the system `Menu`, never
by a new color. Phase 9 introduces no new color and changes no asset.

|---------|------|

| Filter item labels | Languages: `L10n.languageFrench`, `L10n.languageEnglish`; Session types in order conference, quickie, codelab (`L10n.sessionTypeConference`, `...Quickie`, `...Codelab`); Complexity in order beginner, intermediate, advanced (`L10n.complexityBeginer`, `...Intermediate`, `...Advanced`); Rooms: one item per room, label `room.name`, same order as the rooms list today |
| Day picker | `L10n.day1`, `L10n.day2` (unchanged; dates stay a single-source constant, 07 D-07) |
| Loading state | `L10n.loading` "Loading..." / "Chargement..." (first load only) |
| Empty state heading | none in v1.0 — the agenda renders an empty list with no message when the day or filters yield no session. `L10n.emptyDay` exists but is unused. **Parity: do not add one in this phase** (logged as debt, a new empty state is a visible change) |
| Empty state body | none (same reason) |
| Error state | none visible. Failure before the first emission: log through `DevFestLogger`, `isLoading = false`, empty list. Failure after the first emission: log, keep the last content, stop (D-04). No retry, no alert, no banner (pinned v1.0 debt) |
| Destructive confirmation | Clear filters (`L10n.filterClear`): no confirmation, immediate, as in v1.0. Clearing writes an empty set through the store (D-06). Removing a bookmark: no confirmation, immediate |

## Interaction and Behavior Contract (Phase 9 additions to the frozen UI)

These rules bind the executor where the data path changes under unchanged views.

1. **Views change as little as possible** (D-07). The row, header, picker, menu, detail and tab layouts
   keep their structure, modifiers, spacing and typography exactly. Only data sources, bindings and
   intents change. The parity diff must be readable.
2. **Observation lifetime** (D-01). The combined flow is collected in `AgendaView`'s `.task`, cancelled
   when the view disappears, resubscribed on appear. `RCValues.sharedInstance.fetchCloudValues()` stays in
   the same `.task`, before the collection starts, in its current order.
3. **Writes** go through the VM intents (`toggleBookmark`, `toggleFilter`, `clearFilters`, or an
   equivalent settable property) that write through the Kotlin stores and update the mirror
   synchronously (D-05, D-06). Views never filter, group or persist.
4. **Filter menu structure is identical to v1.0**: same entries, same order, same checkmark
   semantics, same labels (Claude's discretion only on whether option lists come from Kotlin enums
   or Swift literals, provided items, labels and order do not change). The Rooms menu compares by
   `room.id` (parity-safe, `room.id == room.name`).
5. **Scroll to the current slot** keeps its v1.0 behavior (first appearance only, only when the
   device date equals the selected conference day, scrolls to the latest slot not after "now", anchor
   `.top`). Its selection logic becomes a pure function tested with an injected "now" (D-11); no
   visual or timing change.
6. **Day selection** keeps the segmented picker, the two hardcoded 2025 days and the "today if it is
   a conference day else day 1" rule. The constants become single-source (07 D-07 debt).
7. **Session classification**: the star is shown on `isATalk` sessions and the chevron/push link only
   on `isNavigable` ones, now delegating to `ClassifySessionUseCase`; the same sessions as in v1.0
   must be tappable and starrable (verified in the D-10 screenshot set).
8. **Speakers and Venue** (A-Z index, venue language) keep first-emission-only loading and
   reload-on-appear (08 D-09/D-10); only their data source moves to the shared use cases. No layout
   change.
9. **No new UI** is created for the update itself (no migration notice, no spinner, no alert).
