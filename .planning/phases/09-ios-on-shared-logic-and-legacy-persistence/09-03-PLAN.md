Facts (verified while planning):
- `SpeakerIndexUseCase` has `init()`, `letterGroups(speakers:)` returning `[SpeakerLetterGroup]` (`letter`, `speakers`), sorted by letter, speakers in input order. `VenueLanguageUseCase` has `init()` and `languageFor(languageCode:)` taking `String?` and returning `ContentLanguage` (French for `"fr"`, English otherwise, including nil and empty).
- `SpeakersView` calls `getAlphabets()` and `speakers(for:)`, several times per render. Compute the groups once, when `speakersContent` changes, not on each call.
- `SpeakersVenueCharacterizationTests.speaker_alphabet_matches_the_golden` assigns `viewModel.speakersContent` directly on a default-built ViewModel, then reads `getAlphabets()`. A `didSet` on `speakersContent` keeps that test valid with no edit. `@Observable` supports `didSet`: `AgendaViewModel.sessionFilters` already relies on it.
- `venue_language_matches_the_shared_table_for_the_run_locale` calls `VenueViewModel().currentLanguage`: keep that computed property.
- `SpeakersViewModelTests.live_source_...` builds `LiveSpeakersSource(store: { store })` and its doc says no Koin is involved. Pass an explicit `speakerIndex: { SpeakerIndexUseCase() }` there to keep that true.
- STATE.md note "revisit in Phase 9" (speaker index, an `ı` speaker before an `i` speaker): that limit concerns `firstIndexes`, used by the Android scroller. iOS uses `letterGroups`, which keeps both speakers in one `I` group in input order, the same result as v1.0 `speakers(for:)`. No change is needed on iOS; record this in the SUMMARY.
- `Locale.current.languageCode` is deprecated and kept on purpose: Phase 12 owns deprecations (`08 deferred-items.md`).
