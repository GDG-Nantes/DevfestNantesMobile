<objective>
Give the kotlinx-datetime bump a real regression signal, then bump the Firebase/kotlinx dependency group (D-01 stage 5) including the kotlinx-datetime 0.8.0 `Instant`/`Clock` migration.

Purpose: 02-RESEARCH.md § Wave 0 Gaps flags that this project's only `commonTest` file asserts `assertNotNull` and nothing more, so it cannot distinguish "the date logic still works" from "the date logic still returns something". kotlinx-datetime 0.7.0 removed `kotlinx.datetime.Instant`/`Clock` in favour of the stdlib's `kotlin.time` equivalents, and `ScheduleSlot.kt` and `Agenda.kt` both sit squarely on that surface — one parses two ISO strings into epoch milliseconds, the other buckets sessions into conference days via `Instant.minus(...).inWholeDays`. Whether 0.8.0 still typealiases the old package is RESEARCH assumption A2, explicitly unconfirmed. Worse, the documented failure mode is platform-asymmetric: JVM and Android can compile while Kotlin/Native klib resolution fails later. So the test lands first, green on the old version, and the bump follows.

Output: two revertible commits (the date-parsing test; the Firebase/kotlinx bump), both green on `android.yml` and `ios.yml`.
</objective>
