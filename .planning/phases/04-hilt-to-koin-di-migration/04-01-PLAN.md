## Phase-wide conventions (every later plan follows these)

- Each Gradle module exposes one public Koin `Module` val in `<module package>.di` (file `di/XxxModule.kt`). KMP modules that `:shared` exports (`core:data`, `core:analytics`) and `core:network` mark every public Koin val/function `@HiddenFromObjC` (import `kotlin.native.HiddenFromObjC`; the convention opt-in added here removes per-file `@OptIn`). Platform parts are `internal expect val xxxPlatformModule: Module` with actuals on android, jvm AND ios, pulled in through `includes(...)` (RESEARCH Pattern 2, Pitfall 6). They arrive in 04-02.
- Implementation bindings are declared concrete-primary with `bind` (`single { Impl(get()) } bind Interface::class`) so `verify()` inspects the implementation constructor (RESEARCH Pattern 1). ViewModels use `viewModelOf(::X)`; parameterized ones use `viewModel { (id: String) -> X(get(), get(), id) }`.
- Tests that touch Koin live in a `di` package directory and resolve through the `KoinApplication` returned by `initKoin`/`startKoin`/`koinApplication` (no `KoinPlatform` import in tests); `@AfterTest stopKoin()` in KMP tests.
- Koin is resolved at a Compose call site only through `koinViewModel()` default parameters (D-10). `by inject()` exists only in `DevFestNantesApplication`/`MainActivity` (D-11, plan 04-06). Temporary Hilt-to-Koin bridges exist only inside the Hilt `AppModule` (D-06).
- Branch: one phase branch `gsd/phase-4-hilt-to-koin-di-migration` and one draft PR (D-05). Both workflows only run on `pull_request` to `main`. Push after every task commit (rate-limit checkpointing); CI must be green on each plan's final HEAD.

## Choices made here (Claude's discretion, recorded)

- Koin 4.2.2 with a plain `version.ref`, no BOM (RESEARCH Standard Stack; spike-proven on Kotlin 2.4.20/AGP 9.4/Gradle 9.7.1/K/N).
- `dataModule` declares `single { GraphQLStore(get()) } bind DevFestNantesStore::class` and `networkModule` declares `single<ApolloClient> { apolloClient }`. This is byte-for-byte what the store builder's non-mock branch did (`GraphQLStore(apolloClient)`), but it gives `networkModule` a real consumer and lets `verify()` see the ApolloClient edge (RESEARCH Open Question 1). The store builder stays unchanged for tests and the exported Swift API.
- `core:model` declares no Koin module: it has zero bindings (flagged assumption FA-04-05).
- `IosDependencies` is a plain `object` without `KoinComponent` (RESEARCH Pattern 3: keeps Koin protocols out of `shared.h`). D-04 gave `KoinComponent` only as an example, and its "iOS-callable `initKoin` wrapper" is `IosDependencies.shared.start()` (a top-level `init*` function would be renamed `doInit*` by K/N).
- Production `initKoin` calls `allowOverride(false)` before `appDeclaration()`, so a duplicate binding across per-module modules fails at start-up instead of silently winning (DI-02 adjacency edge). Tests that override call `allowOverride(true)` in their `appDeclaration`.
- No Koin logger is configured anywhere (ASVS V7, T-04-04).
