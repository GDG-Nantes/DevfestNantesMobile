# Technology Stack

**Project:** DevFest Nantes, milestone v1.1 iOS Architecture
**Researched:** 2026-10-23
**Scope:** Only the stack additions and changes needed for the new work (shared KMP domain, modular SPM iOS app, explicit DI, iOS 17 + `@Observable` + Swift 6, iOS tests in CI). The validated v1.0 stack (Kotlin 2.4.20, AGP 9.4.0, Gradle 9.7.1, Compose BOM, Apollo 5.2.0, Koin 4.2.2, Firebase BOM, Coroutines 1.11.0, kotlinx-datetime compat pin) is NOT re-researched.
**Overall confidence:** HIGH on the Swift/SPM/KMP-interop decisions. They rest on official release pages and on experiments I ran in this repo's toolchain (see "Verified experiments"). MEDIUM on the CI release/archive path, which still needs a phase-level spike.

## Headline Decisions

| Question | Decision | Confidence |
|----------|----------|------------|
| SKIE vs KMP-NativeCoroutines | **Keep KMP-NativeCoroutines 1.0.6. Do not add SKIE.** | HIGH |
| How SPM packages see the `shared` framework | **Kotlin XCFramework in a local `KotlinShared` package via `.binaryTarget(path:)`.** Drop the Xcode `embedAndSign` direct integration. | HIGH (verified) |
| Swift export | **Do not adopt.** Alpha in Kotlin 2.4.x, works only with direct integration (incompatible with the binaryTarget approach). | HIGH |
| Swift 6 vs Kotlin types | **One Kotlin-boundary package** with `Sendable` gateways and `@retroactive @unchecked Sendable` model conformances. `@preconcurrency import` alone does not work. | HIGH (verified) |
| Test stack | **Swift Testing (bundled with the toolchain) + `UIHostingController` smoke tests + an `.xctestplan`.** No ViewInspector, no snapshot library in v1.1. | HIGH / MEDIUM |
| CI image | **`macos-26` (Xcode 26.6, Swift 6.3.3), arm64.** Package manifests at `swift-tools-version: 6.0`. | HIGH |
| iOS DI | **Plain Swift composition root (no library).** Koin stays Kotlin-side behind `IosDependencies`; no Koin types in Swift. | HIGH |
| Persistence for shared bookmarks/filters | **Hand-written `NSUserDefaults` implementation in `core:data` `iosMain`, reusing the legacy keys.** No new KMP settings library. | MEDIUM-HIGH |

## Alternatives Considered

| Category | Recommended | Alternative | Why Not |
|----------|-------------|-------------|---------|
| Flow/suspend bridging | KMP-NativeCoroutines 1.0.6 | **SKIE 0.10.15** (supports Kotlin 2.4.20, released 2026-09-25) | The project already uses KMP-NC, and the diff is zero. SKIE rewrites the framework at link time with swiftc, so every Kotlin bump has to wait for a matching SKIE release. It generates Swift that has had Swift 6 compile failures (issue #179, closed). Open issue #131: a framework named `shared` collides with Kotlin `object` `.shared` in SKIE's generated suspend wrappers, and `IosDependencies` is exactly such an object. SKIE's headline value is exposing sealed classes, enums and default args. This app does not need those. PROJECT.md already scopes shared ViewModels out. |
| Flow/suspend bridging | KMP-NC | **Kotlin Swift export** | Alpha in 2.4.x. Documented to work only with direct integration, not with SPM binary targets. It would block the modular-package goal. The KMP-NC shims (`asyncFunction(for:)` no-ops) keep the door open for later. |
| Framework exposure | Local XCFramework `binaryTarget(path:)` | Keep `embedAndSignAppleFrameworkForXcode` in the app target | Packages cannot see a framework embedded at the app level. This only works if all `import shared` stays in the app target, which defeats feature packages. Kotlin's own docs list direct integration as the app-level path. |
| Framework exposure | Local `binaryTarget` | Remote `binaryTarget(url:checksum:)` | Needs a hosted release asset per commit. Overkill for a monorepo. Kotlin 2.5.0-Beta1 will generate `Package.swift` for this, which is not relevant yet. |
| Framework exposure | One umbrella `shared.xcframework` | One framework per KMP module | Reintroduces the v1.0 "three-framework problem" (duplicate Kotlin runtime). |
| Swift 6 handling | Gateway + `@unchecked Sendable` model extensions | `@preconcurrency import shared` / `@preconcurrency import KMPNativeCoroutinesAsync` | Tested: it does not silence the `sending ... risks causing data races` error on `asyncFunction(for:)`. |
| Swift 6 handling | Swift 6 mode | Stay on Swift 5 mode in packages | Contradicts the milestone goal. |
| DI | Hand-written composition root | **Factory 3.5.1** | A global container, which is the service-locator pattern this milestone removes. |
| DI | Hand-written composition root | **swift-dependencies 1.17.1** | `@Dependency` is also a locator. It pulls swift-syntax and macros, which costs build time. Good test ergonomics are not worth that for ~10 ViewModels. |
| DI | Hand-written composition root | **Swinject 2.10.0** | Runtime resolution, last release September 2025, no Swift 6 story. |
| DI | Swift composition root | Exposing Koin to Swift | Breaks the v1.0 rule of "no Koin names in `shared.h`". Constructor injection from a Swift `AppContainer` is simpler and testable without Kotlin. |
| Persistence | Hand-written `NSUserDefaults` actual | multiplatform-settings (russhwolf) | Last release 1.3.0 in November 2024, and no Kotlin 2.4 evidence. It would add a dependency for ~40 lines. |
| Persistence | `NSUserDefaults` | DataStore KMP | Async API and a new on-disk format would force a migration on both platforms. Violates strict parity. |
| SwiftUI testing | `UIHostingController` smoke | **ViewInspector 0.10.5** (2026-09-30) | Relies on SwiftUI internals via reflection. It needed fixes for iOS 27 / Xcode 27 (issues #425, #442). Only adds value for asserting view content, which v1.1 does not require. If added later, pin exactly. |
| SwiftUI testing | `UIHostingController` smoke | **swift-snapshot-testing 1.19.7** (2026-10-21) | Baselines drift across Xcode and simulator OS versions, a flaky-CI risk for a "no visible change" milestone with 26.x-only simulators. Defer to a visual-regression milestone. |
| Project generation | Hand-edited `.xcodeproj` plus local packages | Tuist / XcodeGen | Extra tool and migration with no benefit for one app target. |

## What NOT to Add

- **SKIE** (see above). Revisit only if sealed-class/enum ergonomics become a real need.
- **Combine / `KMPNativeCoroutinesCombine`**. Delete the product dependency and every `import Combine`.
- **RxSwift, KMPNativeCoroutinesRxSwift**. Pulled transitively by the KMP-NC package manifest but never linked. Do not reference.
- **Swift DI frameworks** (Factory, Swinject, swift-dependencies, Needle).
- **A Kotlin settings library** (multiplatform-settings, DataStore).
- **ViewInspector and snapshot libraries** in this milestone.
- **swift-testing as a package dependency** (the toolchain ships it).
- **Kotlin Swift export, Compose Multiplatform, shared ViewModels** (already out of scope).
- **CocoaPods remnants.** `shared.podspec`, the "Check Pods Manifest.lock" build phases and `HEADER_SEARCH_PATHS = Pods/...` in `project.pbxproj` are dead. Remove them during the project clean-up. The validated list in PROJECT.md still says "via Cocoapods", which is stale.

## Verified Experiments (run 2026-10-23 on this machine, Xcode 27.1 / Swift 6.4)

1. **Swift 6 plus KMP-NC.** A `@MainActor` class holding a non-Sendable ObjC store and calling `try await asyncFunction(for: store.getXNative(...))` fails with `sending 'self.store.getXNative' risks causing data races`. `@preconcurrency import KMPNativeCoroutinesAsync` does not fix it. Iterating `for try await x in asyncSequence(for: store.xNative)` directly inside the `@MainActor` type compiled without diagnostics. A nonisolated `struct Gateway: @unchecked Sendable` that calls `asyncFunction`, wraps `asyncSequence` in an `AsyncThrowingStream` (store captured with `nonisolated(unsafe) let`), and returns models marked `extension Model: @retroactive @unchecked Sendable {}` compiled cleanly in Swift 6 mode. The KMP-NC package is itself built in Swift 5 mode (`swiftLanguageVersions: [.v5]`), so it does not leak diagnostics, but its call signatures are not Sendable-annotated. **Boundary rule:** feature code never calls `asyncFunction`/`asyncSequence` directly.
2. **Local XCFramework package.** The repo's real `shared.framework` (iosSimulatorArm64 debug) was wrapped with `xcodebuild -create-xcframework`, put in a local `KotlinShared` package (`binaryTarget(path:)`), and imported by a second local package built in Swift 6 mode with an `@Observable @MainActor` ViewModel that called `IosDependencies.shared.start()`. `xcodebuild test` on an iPhone 17 simulator ran Swift Testing (`@Test`, `#expect`) and a `UIHostingController` render test with no host app: **TEST SUCCEEDED**. First link failed with undefined `_sqlite3_*` symbols until `linkedLibrary("sqlite3")` was added. A `path:` pointing outside the package root (`../../out/shared.xcframework`) also resolved and built.
3. **Toolchain facts.** `macos-latest` is macOS 26 arm64 with default Xcode 26.6. Xcode 26.4 shipped Swift 6.3, and 26.6 contains Swift 6.3.3. Xcode 27 shipped 2026-09-14 with Swift 6.4. The runner's Xcode 27 is a separate preview image (`xcode-27`, macOS 27).

## Integration Points and Guardrails

- **Version gate script.** Add `scripts/native-coroutines-version-gate.sh` (same style as `di-gate.sh`) that fails CI if `kmpNativeCoroutines` in `gradle/libs.versions.toml` differs from the `exact:` version in the Core bridge `Package.swift`. This catches today's ALPHA-45 vs 1.0.6 mismatch.
- **Dev loop.** The XCFramework must exist before Xcode resolves packages. Provide one script (`scripts/build-shared-xcframework.sh`) that runs the Gradle task and copies or points to `iosApp/Packages/KotlinShared/`. Gitignore the artifact. Wire it into the README/DEVELOPMENT quick start. Changes made in Android Studio will not appear in Xcode until it is re-run (a known drawback of this approach).
- **Framework must stay static** (`isStatic = true`) and umbrella (`export()` of `core:model`, `core:data`, `core:analytics` and now `core:domain`). Keep `SharedFrameworkPlaceholder.kt`. Keep `swift-names-gate.sh` and extend it to the new module's exported names.
- **Model stubs for tests.** `core:model` ships `SessionFixtures`, `SpeakerFixtures` and so on in `commonMain`, so they are visible in the framework. Swift Testing ViewModel tests can build realistic Kotlin models without a mocking library. This matches the "hand-written fakes, no mocking" rule. Confirm visibility when exporting.
- **Kotlin plugin parity.** `:core:domain` must apply KSP and `kmp.native.coroutines` like `core:data`, and keep the `ExperimentalObjCName` / `ExperimentalObjCRefinement` opt-ins from the convention plugin. Prefer named use-case methods over `operator fun invoke` for Swift call sites.
- **Deployment target.** Set `IPHONEOS_DEPLOYMENT_TARGET = 17.0` on every target (app, tests) and `.iOS(.v17)` in every package. `shared.podspec` still says 15.0 and can go with CocoaPods.
- **Existing XCTest target.** `DevFest NantesTests` has a CocoaPods manifest check phase and is not run in CI. Replace it with the package test targets plus the test plan rather than reviving it.

## Installation

```bash
# Kotlin: no new third-party libraries. Add :core:domain to settings.gradle.dcl and the catalog stays unchanged.
# Swift packages (declared in each Package.swift, not installed globally):
#   KMP-NativeCoroutines   exact: "1.0.6"   (Core bridge package only)
#   firebase-ios-sdk       existing pin     (CoreServices package only)
# Build the framework package input:
./gradlew :shared:assembleSharedDebugXCFramework
# Tools on CI / dev machines:
brew install swiftgen        # already installed in ios.yml (6.6.3)
# Run iOS tests (CI shape):
xcodebuild test -project iosApp/iosApp.xcodeproj -scheme iosApp \
  -destination "platform=iOS Simulator,name=<resolved iPhone>" \
  -enableCodeCoverage YES -resultBundlePath build/ios-tests.xcresult
```

## Open Items for Phase-Level Research

1. **Release/archive path.** A release XCFramework (`assembleSharedReleaseXCFramework`), dSYM and Crashlytics upload (`documentation/iOS_BUILD_DSYM.md`), and a build phase that refreshes the XCFramework without breaking package resolution. Debug is verified; Release is not. (MEDIUM)
2. **Xcode refresh behavior** when the local XCFramework contents change between builds (reports of "module not found" needing a clean). Spike early. (MEDIUM)
3. **iOS 17 floor is not testable on CI.** The `macos-26` image has only iOS 26.x simulators. Either accept compile-time availability checks only, or add an iOS 17.x runtime download step (`xcodebuild -downloadPlatform iOS -buildVersion 17.5`, slow). Decide in the CI phase.
4. **SwiftGen in packages.** Confirm `publicAccess: true` plus the `Bundle.module` branch, and `defaultLocalization` for the `en`/`fr` lproj in `DesignSystem`. (MEDIUM)
5. **Firebase strict-concurrency friction** at the `CoreServices` boundary. Decide per symbol whether to use `@preconcurrency import` or bump to 12.x. (MEDIUM)
6. **Complete the `@retroactive @unchecked Sendable` list** by enumerating the exported model classes and enums. These are safe only for immutable Kotlin types, so add a review checkpoint when a mutable class is exported.
