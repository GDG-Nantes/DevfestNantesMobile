Follow the 04-01 "Phase-wide conventions" and the 04-02 scope-mapping table (D-08). Feature-migration recipe, applied identically in 04-03..04-05:
1. Strip the Hilt ViewModel/injection annotations and their imports from the module's classes (plain constructors, same parameter order).
2. Add `<feature package>.di.<X>Module.kt` with one `val <x>Module: Module` declaring the ViewModels (`viewModelOf`) and any service the module owns (concrete primary + `bind`).
3. Switch each default-parameter resolver at a call site to `koinViewModel()` (`org.koin.compose.viewmodel.koinViewModel`), changing no other parameter.
4. Append the module to `androidModules` (`androidApp/.../di/AndroidModules.kt`).
5. If a Hilt consumer still needs a type this module now binds, turn the Hilt `AppModule` provider into a `KoinPlatform.getKoin().get()` bridge (D-06).
6. Add `feature/<x>/src/test/java/<package path>/di/<X>ModuleTest.kt` with `<x>Module.verify(extraTypes = <upstream types>)`.
7. Remove the now-clean files from `scripts/di-gate-hilt-allowlist.txt` in the same commit.
8. Run the verify and commit as `feat(04-0N): <module> on Koin`, then push.

Create `scripts/di-gate.sh` (bash; `REPO_ROOT` is one level above `scripts/`). Modes:
- no argument or `check` (default);
- `selftest`;
- `hits`, which prints the sorted unique tracked paths matching the Hilt rule. It is used once to seed the allowlist.
Any other argument prints `Usage: $0 [check|selftest|hits]` and exits 1.

Scan set: `git ls-files -- '*.kt' '*.kts' '*.toml' '*.pro' '*.xml' '*.dcl'`, minus anything under `.planning/`. Markdown, HTML and Swift are out of scope; 04-07 updates docs and licenses separately.

Hilt rule, applied to every scanned file. A line hits when it matches either:
- the case-insensitive extended regex for the words hilt, dagger or the `javax.inject` package, or
- the case-sensitive annotation regex `@(Inject|Provides|Binds|Module|InstallIn|EntryPoint|AndroidEntryPoint|HiltAndroidApp|HiltViewModel|AssistedInject|Assisted|AssistedFactory|ElementsIntoSet|Singleton|ActivityScoped|AliasOf)\b`.
A hit in a path absent from `scripts/di-gate-hilt-allowlist.txt` prints `DI-HILT-FOUND <path>:<line>`. An allowlist line that is not a tracked path, or whose file has no hit, prints `DI-ALLOWLIST-STALE <path>`. A missing allowlist file counts as empty (the 04-07 end state).

Service-locator rule, applied to `*.kt` only. A line hits when it matches any of:
- `import org\.koin\.core\.component\.`
- `import org\.koin\.android\.ext\.android\.`
- `import org\.koin\.mp\.KoinPlatform`
- `import org\.koin\.compose\.koinInject`
- `import org\.koin\.java\.KoinJavaComponent`
- `import org\.koin\.core\.context\.GlobalContext`
- `KoinComponent`
- `getKoin\(`
A hit prints `DI-LOCATOR-FOUND <path>:<line>` unless the path is permanently allowed. A path is permanently allowed when it contains `/di/`, or its basename ends in `Module.kt`, or it is exactly one of:
- `shared/src/iosMain/kotlin/com/gdgnantes/devfest/shared/IosDependencies.kt`
- `androidApp/src/main/java/com/gdgnantes/devfest/androidapp/DevFestNantesApplication.kt`
- `androidApp/src/main/java/com/gdgnantes/devfest/androidapp/MainActivity.kt`
`koinViewModel` is allowed everywhere (D-10).

Check mode prints every offending line, then exits 1 if any were printed, else prints `DI-GATE-OK`. Selftest runs the same matcher functions against fixture files written under the mktemp WORK dir, with synthetic repo-relative paths; the gate does not read the fixtures' content from tracked files.

Seed the allowlist: run `bash scripts/di-gate.sh hits > scripts/di-gate-hilt-allowlist.txt`, then review it. It should contain only Hilt-era files: build-logic Hilt files, catalog, root and app build files, `core/ui/build.gradle.kts`, the androidApp shell, and the not-yet-migrated feature and core:ui files. Add a header comment to the script, not to the allowlist (the allowlist is pure paths).
