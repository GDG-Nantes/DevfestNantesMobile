## Grounded facts this plan relies on (verified at planning time, 2026-09-23/24)

- **Which generated class really collides (corrects 03-01-SUMMARY's collision table).** The class that collides with each domain model is Apollo's **schema-type holder** `com.gdgnantes.devfest.graphql.type.{Venue,Session,Speaker,Room,Partner}`: a class holding only a companion with `type: ObjectType` and a nested `Data` interface. It is not the response model `GetVenueQuery.Venue`. Evidence from the current `shared.h`: `@interface SharedVenue_ : SharedBase` has only `init()` + `companion`, and nested names `Venue_.Companion` / `Venue_Data` exist. The response models are nested classes, so their Swift names are dotted (`GetVenueQuery.Venue`, `SessionDetails.Speaker`) and never collided. Renaming the response models (which would need GraphQL aliases, a wire change) would NOT remove the collision.
- **Mechanism: Apollo `@targetName` on OBJECT types.** apollo-ast 5.2.0 defines `directive @targetName(name: String!) on OBJECT | INTERFACE | ENUM | ENUM_VALUE | UNION | SCALAR | INPUT_OBJECT` ("Use the specified name in the generated code instead of the GraphQL name"). apollo-compiler 5.2.0 auto-imports it when the schema has no own kotlin_labs `@link`: `extend schema @link(url: "https://specs.apollo.dev/kotlin_labs/v0.3", import: ["@optional", "@nonnull", "@requiresOptIn", "@targetName"])`. `LayoutImpl.schemaTypeName` resolves class names from `CodegenType.targetName`, and `checkApolloTargetNameClashes` rejects clashing target names. The schema has no `@link` today (`grep -n '@link' shared/src/commonMain/graphql/schema.graphqls` is empty). Source: bytecode strings of `apollo-ast-jvm-5.2.0.jar` / `apollo-compiler-5.2.0.jar` in the local Gradle cache.
- **File pickup.** When `schemaFiles` is not set (it is not, `shared/build.gradle.kts` `apollo { service("service") { ... } }`), the Apollo Gradle plugin 5.2.0 `fallbackFiles` collects `**/*.graphqls`, `**/*.json`, `**/*.sdl` from the service's graphql source directories. So `shared/src/commonMain/graphql/extra.graphqls` is merged with `schema.graphqls` without any Gradle change.
- **Wire/cache neutrality.** `@targetName` changes Kotlin identifiers only. The GraphQL name stays in `ObjectType.Builder(name = "Venue")`, `__typename`, operation documents, operation IDs (a hash of the document) and the normalized-cache plugin's type policies, which are all string literals. Hand-written Kotlin never imports `com.gdgnantes.devfest.graphql.type.*` (`git grep -n 'graphql\.type\.' -- '*.kt'` is empty). It only imports operations and fragments, so GraphQLStore.kt and Mappers.kt need no change.
