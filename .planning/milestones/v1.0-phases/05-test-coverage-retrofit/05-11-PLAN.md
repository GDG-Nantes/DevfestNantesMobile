<objective>
Close UAT gap G-05-3. Session detail crashes with `NoClassDefFoundError: kotlinx/datetime/Instant` as soon as the Remote Config feedback flag is on.

Root cause (debug session `.planning/debug/feedback-kotlinx-datetime-instant-crash.md`): OpenFeedback 1.0.0-alpha.3 was compiled against kotlinx-datetime 0.6.x and links directly against `kotlinx.datetime.Instant`, `Instant$Companion`, `Clock$System` and `TimeZoneKt.toLocalDateTime(kotlinx.datetime.Instant, TimeZone)`. The Phase 02 bump to 0.8.0 (commit 736c843) removed those classes, and three R8 suppression rules hid it on a false "unreachable" premise. No OpenFeedback release fixes it (1.0.0-alpha.6 still pins 0.6.2). `0.8.0-0.6.x-compat` is 0.8.0 plus exactly those classes. The diagnosis proved this with a differential JVM repro.

The fix keeps the newest kotlinx-datetime and does not downgrade to 0.6.2:
- the catalog resolves the compat twin of 0.8.0;
- a CI guard runs OpenFeedback's real code on the app classpath;
- first-party code moves to `kotlin.time.Instant` so the compat classes stay a runtime-only bridge for OpenFeedback;
- the suppressions are removed;
- the end of the compat line (0.8.x) is documented.

The Phase 02 BUILD-06 outcome is amended from "kotlinx-datetime 0.8.0" to its compat twin.

Scope notes:
- D-10 (characterize, don't fix) does not apply. This is a Phase 02 regression of behavior that worked on 0.6.2, found by UAT and routed to gap closure. It is not a pre-existing defect pinned by a Phase 05 test. Restoring it is what the no-regression rule requires.
- The D-23 `FeedbackFlags` seam, `FeedbackFormViewModel` and every Koin module are not touched.

Purpose: the feedback area works again on every feedback-enabled build, and CI catches a regression even though CI builds keep OpenFeedback disabled.
Output: `OpenFeedbackDatetimeLinkageTest`, catalog pin, four import swaps, cleaned `proguard-rules.pro`, STATE.md follow-up, green CI, plus a device re-check of UAT test 3 for the end-of-phase UAT.
