# Requirements: DevFest Nantes App Modernization

**Defined:** 2026-09-12
**Core Value:** CI/CD must work again and the project must become maintainable again (modern build, modular architecture, decentralized DI, solid test coverage) without ever regressing the app's existing behavior for users.

## v1 Requirements

Requirements for this modernization effort. Each requirement maps to one or more roadmap phases.

### CI-IOS (Broken iOS CI)

- [x] **CI-01**: The GitHub Actions iOS CI completes successfully thanks to dynamic simulator resolution (`xcrun simctl list` or an explicitly pinned macOS/Xcode version), fixing the root cause rather than a re-pin that will break again at the next runner image rotation

### BUILD (Dependencies & build system)

- [x] **BUILD-01**: The project compiles with Kotlin 2.4.0
- [x] **BUILD-02**: The project migrates to AGP 9.2.0 and the new `com.android.kotlin.multiplatform.library` plugin (replaces the `kotlin.multiplatform` + `com.android.library` coexistence forbidden in AGP 9+)
- [x] **BUILD-03**: The project uses Gradle 9.7.1
- [x] **BUILD-04**: Compose BOM is updated to 2026.08.00
- [x] **BUILD-05**: Apollo GraphQL is updated to 5.0.1
- [x] **BUILD-06**: Firebase BOM, Kotlin Coroutines, kotlinx-serialization and kotlinx-datetime are updated to their latest stable versions
- [x] **BUILD-07**: Build files are migrated to the Gradle Declarative DSL (`.gradle.dcl`) where AGP/KMP support allows it; unsupported modules stay documented in Kotlin DSL (`.kts`) with the reason for the blocker

> **D-03 version-target deviation (02-01 checkpoint, 2026-09-18):** BUILD-01/02/04/05 pin exact version numbers as they read above, snapshotted 2026-09-12. The developer selected the `newest-verified` checkpoint option in 02-01-PLAN.md: this milestone targets the newest verified stable releases found during each plan's own live re-verification against registry `maven-metadata.xml`, not the literal numbers above. Concretely: Kotlin **2.4.20** (not 2.4.0, BUILD-01 — shipped in 02-01), AGP **9.4.0** (not 9.2.0, BUILD-02 — 02-02), Compose BOM **2026.09.00** (not 2026.08.00, BUILD-04 — 02-03), Apollo **5.2.0** (not 5.0.1, BUILD-05 — 02-03). Each requirement is satisfied by a superset of its literal text; checked off only once its plan ships the newest-verified number. See `02-01-SUMMARY.md` and `STATE.md` § Decisions for the full rationale.

### ARCH (Multi-module architecture)

- [x] **ARCH-01**: The project's build-logic uses convention plugins + the existing version catalog (`libs.versions.toml`), avoiding configuration duplication across modules
- [x] **ARCH-02**: The `core-*` modules (model, network, data, analytics, ui, testing) exist and respect the unidirectional dependency graph (core never depends on feature)
- [x] **ARCH-03**: The `feature-*` modules (agenda, speakers, venue, session-detail, about, settings) exist, each owning its own ViewModel(s) and Compose screens

> **Phase 3 amendment (03-CONTEXT.md D-04..D-06, 2026-09-22):** the per-feature Koin module ships in Phase 4 (DI-02) — Hilt stays in place during Phase 3. `feature-bookmarks` is removed (no screen: `BookmarksStore` → `core-data`, toggle + `BookmarksViewModel` → `core-ui`) and `feature-about` is added (About + Partners).

- [x] **ARCH-04**: `iosApp` keeps consuming a single Kotlin/Native framework (umbrella framework aggregating all KMP modules) despite `shared` being split into several Gradle modules

### DI (Hilt → Koin migration)

- [x] **DI-01**: DI is fully migrated from Dagger Hilt to Koin
- [x] **DI-02**: Each Gradle module (`core-*`/`feature-*`) exposes its own Koin module (`module { }`), composed via a single `initKoin()` entry point
- [x] **DI-03**: Platform-specific dependencies (Android Context, SharedPreferences, etc.) are provided via `expect`/`actual` or per-platform Koin modules
- [x] **DI-04**: ViewModels and Stores use constructor injection — no `get()` calls scattered outside the DI wiring layer
- [x] **DI-05**: A `core-testing` module centralizes the shared fakes/test doubles (in the style of `DevFestNantesStoreMocked`) for all feature modules
- [x] **DI-06**: A Koin `checkModules()` test verifies the complete DI graph in CI

### TEST (Test coverage)

- [x] **TEST-01**: Known blocking fragilities are fixed before extending coverage (unseeded RNG in `StoreStubs.kt`, `SimpleDateFormat` thread-safety in the tested paths)
- [x] **TEST-02**: `commonTest` coverage of business logic (Store/repository, GraphQL→model mappers) is extended by carrying the existing `DevFestNantesStoreContractTest` pattern over to the new `core-data`/feature modules
- [x] **TEST-03**: ViewModel test coverage is extended, made possible by constructor injection (Koin)
- [x] **TEST-04**: Compose smoke tests on critical Android screens are maintained/extended per feature module (`androidTest`), relying on `core-testing`

### CICD (CI/CD optimization)

- [x] **CICD-01**: The Gradle cache (`gradle/actions/setup-gradle`) is configured in CI
- [x] **CICD-02**: The Konan cache (`~/.konan`) is configured in CI to speed up Kotlin/Native compilation
- [x] **CICD-03**: Android and iOS jobs are split into a CI matrix (`ubuntu-latest`/`macos-latest`)

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| New user features / UX changes | Purely technical effort — the app must behave exactly the same after the modernization |
| Full NIA taxonomy (`sync`, `benchmark`, `lint`, `test-app` modules) | Solves scale problems that a single conference app does not have — scope creep |
| Per-screen modularization (one module per screen) | Over-modularization — the Gradle configuration cost would exceed the benefit for ~6 features |
| Compose Multiplatform (shared UI) for iOS | iOS stays in native SwiftUI — sharing the UI would be a UI rewrite with regression risk, out of scope |
| Numeric % test coverage target | Explicitly rejected — qualitative priority on business logic rather than an arbitrary number |
| Mocking-framework-heavy testing (MockK/Mockative) by default | The project already favors fakes (`DevFestNantesStoreMocked`) — a pattern to extend, not replace |
| Koin `get()` calls in service-locator style scattered through business code | Recreates the untestable coupling that the DI migration is meant to solve |
| Running the full iOS build+test on every commit of every branch | High CI cost (macOS runners) without proportional safety benefit — handled later via filtered triggers (v2) |
| Visual regression tests (Paparazzi/Roborazzi) | Not selected by the user for this milestone |
| Staying on AGP 8.13.0 | Decision made: migration to AGP 9.2.0 + new KMP plugin from the start of the effort |
| Deadline tied to the next DevFest Nantes edition | No strict date constraint — progress phase by phase |
