<objective>
Fix Phase 9 code review finding WR-01: the iOS bookmark mirror in `AgendaViewModel` is seeded once from the first emission of `BookmarksStore.bookmarkedSessionIds`, and nothing recovers it when that seed fails or has not run yet. In that state the star of a stored bookmark is empty and a tap writes `bookmarked: true` (a no-op in the store) and sends the wrong analytics value.

Chosen fix (per D-06, "exact port methods are Claude's discretion"): add a synchronous per-session snapshot read to the `AgendaSource` port, implemented by `LiveAgendaSource` over the existing Kotlin `BookmarksStore.isBookmarked(id:)`. While `bookmarksSeeded` is false, `isBookmarked` and `toggleBookmark` take the current value from the store instead of the empty mirror. This keeps the D-05 design: the ViewModel stays the single iOS writer, every intent still updates the mirror synchronously and writes through `setBookmarked`, and persistence stays only in Kotlin. Only `LiveAgendaSource` reaches Kotlin (08 D-04/D-05).

Rejected alternative: keep the bookmark flow collected for the life of `observeAgenda()`. It needs a second concurrent collection inside the D-01 `.task` and changes the "seeded once per ViewModel" contract and its tests. It also does not cover the Speakers > speaker > session path, where `observeAgenda()` may never have run.

Scope is strictly WR-01. IN-01 to IN-05, the seed/toggle race while the first emission is in flight, and any Kotlin or Android change are out of scope. The 09-CONTEXT decision record is left unchanged as history. `documentation/ARCHITECTURE.md` is updated only because AGENTS.md requires docs to follow a behavior they describe: the D-05 first-load stale star it lists as an accepted deviation no longer exists.

Purpose: a stored favorite always shows and toggles correctly, whatever happened to the one-shot seed.
Output: port method + live adapter + fake, ViewModel fallback, four new Swift Testing tests (72 to 76), the doc update, and the WR-01 ledger row set to `fixed`. Three local commits on `feature/reno_phase_9`. Do NOT push: PR #433 is open and the maintainer pushes.
</objective>
